# The dodge's token-level mechanics at the thinking boundary (ticket #94)

- **Ticket:** [kido5217/ninfer-yarn#94](https://github.com/kido5217/ninfer-yarn/issues/94), parent map [#95](https://github.com/kido5217/ninfer-yarn/issues/95).
- **Baseline:** `master` @ `e83a9af5`. All line references are to that commit.
- **Raw evidence:** `/tmp/opencode/e2e/constrained-thinking-default/raw3/G1..G4.json` (probe @ `e83a9af5`, explicit `enable_thinking:true` + `response_format` json_schema), `/tmp/opencode/graphiti-probe/raw2/A*.json` (baseline @ `55c67615`, thinking-on constrained arm), `/tmp/opencode/graphiti-probe/raw/T*.json` (first probe), `/home/kido/trash/temp/ninfer-yarn-log.jsonl` (request log, rids 30–33).
- **No live run** (RTX 5090 busy, ~22 GiB held by the production serve). The trace that would settle the residual question is specified in §7.

## 1. Question

What exactly happens, token-level, when the model dodges the schema under thinking-on + constrained: after `</think>`, what does the answer region contain, why does the request end `finish_reason=stop` with empty `content`, what does the mask admit at the boundary, and did the model ever enter the answer region at all?

## 2. Core answer (quotable)

**The model *does* emit `</think>` — but immediately followed by `{`, never by a format-whitespace byte. The parser's R2 close rule requires `</think>` + whitespace (`chat_parse_core.cpp:612–623`, `is_format_whitespace` = space/tab/CR/LF, `:34–36`), so the marker is classified as quoted protocol text (R3), the parser never leaves the Reasoning phase, and every subsequent byte — the whole schema answer, drafted with the model's own keys — is published to the reasoning channel. Because the mask schedule is derived from the parser phase (`preview_reasoning_flags`), the dodge also disables the grammar: as long as the split never happens, no plan contains an answer column, the device mask stays inactive (`decode.cpp:877–892`) and the grammar state is not advanced (`commit.cpp:430–435`). At most the single column a draft span marks as the boundary can be masked, and that column's root row forbids the whitespace the parser needs (§5) — even an in-round boundary plan cannot complete the split. The model finishes with a natural EOG/EOS (`finish_reason=stop_token` in the request log; `stop` in the OpenAI response, `openai_chat_response.cpp:122–129`), the terminal flush takes the `ended_in_reasoning` branch and appends an empty content delta (`output_session.cpp:358–371`), so `content` is empty while `finish_reason` is `stop`.**

Put differently: the failure is a **two-rule deadlock**. The parser only accepts a boundary byte that is whitespace; the answer grammar's root row (where the boundary column is masked) only admits the schema's first byte (`{`). If the mask is ever engaged on the deciding column it forces the model *away* from the whitespace the parser needs (the grammar root has no leading `space`, `json-schema-to-grammar.cpp:743`), and the model's own observed behavior — `</think>{` — does the same. The model does not "stop before answering": it writes the complete answer as reasoning, unconstrained, because the boundary was never recognized.

## 3. Mechanism, step by step

1. **Thinking-on constrained requests start in the Reasoning phase, mask off.** The template leaves `<think>` open, `starts_in_reasoning` is true, and the core's initial phase is Reasoning (`chat_parse_core.cpp:724–727`). The prefill bonus sample asks for the committed region with an empty span (`engine_core.h:1414–1419`) and gets Reasoning → all-ones.
2. **Per round, the mask plan is computed from the MTP draft span.** `run_decode_round` reads the drafts (`engine_core.h:1843–1845`) and calls `preview_reasoning_flags(drafts)`; flag j is the phase after consuming column j's bytes, read-after-feed so the completing token is itself a 0 column (`output_session.cpp:447–462`, contract at `output_session.h:70–81`).
3. **While the committed phase stays Reasoning, no answer column is masked.** `fill_round_rows` gives every region-1 column all-ones and never advances its preview through it (`grammar_runtime.cpp:48–63`); `refresh_mask_rows` lowers the device `mask_active` flag when no column of the round is masked (`decode.cpp:877–892`); `advance_grammar_state` skips a fully-reasoning plan (`commit.cpp:430–435`). A round whose drafts contain `</think>` + whitespace can plan one boundary column (§6 scenario M), but the accepted byte at it cannot be whitespace (§5).
4. **The model finishes reasoning and emits `</think>` → `{`.** In all 20 saved failure responses the byte immediately after the close marker is `{` (0 whitespace; see §4 table). The parser holds a complete marker until the next byte decides (R4, `chat_parse_core.cpp:644–649`); the next byte `{` is not format whitespace, so R3 applies: the marker is republished as reasoning (`:650–655`) and the phase stays Reasoning. The marker is not "swallowed" — it appears verbatim in `reasoning_content`.
5. **The model continues the JSON answer as reasoning text.** With the phase stuck, the mask stays off and the bytes flow unconstrained. The saved payloads are *complete, valid JSON* whose keys are the model's own (`entities`/`facts`) instead of the schema's `extracted_entities`/`edges` (schema: `/tmp/opencode/graphiti-probe/schemas.json`; verified by parsing the tails of G1–G4 and A2/A3). A grammar-constrained completion cannot produce that shape: the converter emits required properties before optional/additional ones, so the first key after `{` must be one of the required properties, and a complete value must contain `extracted_entities` and `edges` (`json-schema-to-grammar.cpp:698–746`); `accept`/commit would fail-closed on anything else (`grammar_runtime.cpp:66–77`, `commit.cpp:451–455`). No request_error exists (33 `request_done`, 0 error in the window; `serve.log` clean), so no answer column was ever grammar-fed.
6. **The model emits EOG/EOS.** Request log rids 30–33: `finish_reason: "stop_token"`, `completion_tokens` 2652/2468/3181/2482, all counted as reasoning (OpenAI usage `completion_tokens_details.reasoning_tokens` = completion_tokens). No thinking budget was configured (`thinking_budget: null`, `thinking_control_applied: false`), so this is the model's natural stop after finishing its JSON — not a cap, and not a mask-admitted EOS (no answer plan was active; §6).
7. **Terminal flush exposes empty content.** `flush_terminal` with `ended_in_reasoning=true` appends the terminal reasoning delta, closes reasoning, and appends the (empty) content delta (`output_session.cpp:366–371`). The serve maps `StopToken → "stop"` (`openai_chat_response.cpp:124–129`). Hence `content:""`, `finish_reason:"stop"`, everything in `reasoning_content`.

## 4. Evidence from the raws (all 20 close-in-reasoning entries)

Every saved response that has `</think>` anywhere in `reasoning_content` (= every thinking-on failure) has `{` as the immediately following byte, and empty `content`:

| Files | close-in-reasoning | byte after `</think>` | content |
|---|---|---|---|
| `raw3/G1..G4.json` (4) | yes | `{` | empty |
| `raw2/A2,A3,A5,A6.json` (4) | yes | `{` | empty |
| `raw/T2-json_object-*` (3), `T3-combined-*` (3), `T4-timestamps-*` (3), `T5-extracted_entities-0` (1), `T6-empty-*` (2) | yes | `{` | empty |

The thinking-on **successes** are exactly the cases where the marker was consumed by the parser (it appears in neither channel) and content starts with `{`: `raw2/A1,A4` and `raw/T3-direct-0`, `T5-summarized-0` (content 2444/2400/2280/118 chars). So the discriminator between success and dodge in every saved sample is precisely the byte after `</think>`: whitespace → split + constrained answer; `{` → quoted-marker classification + dodge.

Quantitative: of the 10 thinking-on constrained samples in the two probe arms (A: 6, G: 4), all 10 closed thinking — 8 dodged with `</think>{`, 2 succeeded with the close consumed. Across all three raw directories, 20/20 close occurrences are `</think>{`.

## 5. What the grammar mask admits at/after the boundary

- **Root row = the JSON-schema initial state.** The serve converts `response_format` json_schema with the vendored converter (`constraint_contract.cpp:339–351`, `json_schema_to_grammar(common_json::parse(...), force_gbnf=true)`; conversion at `json-schema-to-grammar.cpp:993–1012`, root visit `:1010–1011`). An object rule starts with the literal `{` and optional `space` *inside* the object (`:743–746, :791`; `SPACE_RULE` at `:229` is `| " " | "\n"{1,2} [ \t]{0,20}`, used after `{`, `[`, `:`, `,` — never before the root). `root` is the object rule itself (rule naming `:878–880`). **Therefore a whitespace-only token (the natural `</think>\n` tokenization) is NOT admissible at the initial row.**
- **EOS/EOG at the root: not admitted.** `GrammarState::accept` returns `can_end()` for an EOG id (`grammar.cpp:118–140`), and the producer sets EOG bits only `if (can_end)` (`trie_producer.cpp:2246–2267, :2320–2322, :2340–2343`). The initial state cannot end (the value must complete), so EOG is off at the boundary row.
- **What that means for the deciding column.** The column that completes the close is a region-0 column masked with the *pre-boundary* row (`fill_round_rows` uses `row_for(preview)` where `preview` was never advanced by region-1 columns; `grammar_runtime.cpp:48–58`). With the current converter that row forbids whitespace, so if the plan ever recognizes the boundary in-round, the mask pushes the model off `\n` to a root-admissible token such as `{` — producing exactly the observed `</think>{` and the R3 non-close. The parser's requirement and the mask's row are mutually exclusive.

## 6. Reconciliation with #92 (`mask-activation-boundary.md` @ `b7095db4`)

#92 established: reasoning is never masked, the mask first engages on the transition column with the pre-boundary row, and "if the boundary is never completed the mask never engages at all". Its residual #1 conjectured "the usual `</think>` + `\n` tokenization" and its un-settled alternatives were (a) the model never attempted the close, or (b) the transition column's mask rejected the deciding token.

#94 sharpens this with the raw text: **the model did attempt the close — the marker is present — but the accepted byte after it was `{`, never whitespace.** So #92's (a) is false as stated, and (b) becomes two remaining sub-cases that the raws cannot separate:

- **Scenario M (mask-displaced):** a round's draft span contained `</think>` + whitespace; the plan marked the decider column 0; the root row rejected the whitespace; the sampler's best admissible token was `{`; the parser then refused the boundary and the answer continued unmasked.
- **Scenario C (model-chosen):** no round ever had a region-0 column at the boundary; the model emitted `</think>{` itself, so the mask never engaged at all.

Both end in the identical published stream. #92's other claim — the answer written under an active schema shows reasoning tokens are not masked — is confirmed and is in fact *why* the dodge cannot be schema-valid: the grammar only ever sees the answer if the parser split first.

## 7. Residual uncertainty and the trace that settles it (GPU-gated)

Open questions a live trace must answer:

1. **M vs C**: did any round's `MaskPlan.reasoning_mask` contain a 0 bit at/after a draft `</think>`, and at that column was the pre-mask argmax a whitespace token displaced by the root row (M), or did no such column ever exist (C)?
2. **Tokenization of the boundary**: the token ids/pieces of `</think>` and of the following token(s) in the Qwen3.8 vocab (is `</think>` one token? is the decider a separate `{` token? does a `\n` candidate ever appear in the pre-mask top-k at that column?).
3. **The EOG token and the final round's plan**: which id ended the turn, was the final round's plan all-reasoning (natural stop, as the request log implies) or answer-masked.

Trace spec (same style as #92's, one run of the same G payload, `enable_thinking:true` + CombinedExtraction schema, `--log-level trace`, artifact/profile identical to the probe, in a scratch worktree with instrumentation):

- per decode round in `EngineCore::run_decode_round` (`engine_core.h:1831–1851`): draft token ids **with decoded text**, `preview_reasoning_flags` output, `MaskPlan.reasoning_mask`, and after `refresh_mask_rows` (`decode.cpp:862`) whether any column was masked;
- at every masked column in `GrammarRuntime::fill_round_rows` (`grammar_runtime.cpp:33`): the state's `can_end`, and the row's bits for the whitespace tokens (`\n`, `\n\n`, ` `) and `{` — confirming the root-row rejection in situ;
- at the sampler (`decode.cpp:56–66` and the MTP/prefill sites): pre-mask argmax and top-k, plus the accepted token per column — this is what separates M from C;
- parser side: log each `</think>` occurrence with the byte that follows it and the committed phase per round (`chat_parse_core.cpp:790–792`).

Expected discriminations: M ⇒ a flag-0 boundary column exists and the accepted token differs from the pre-mask argmax at it (mask displaced a whitespace decider); C ⇒ no flag-0 column exists for the entire turn and the accepted stream is `</think>{` from the model.

## 8. What a mask/parser change for routes (a)–(c) must alter

The deadlock gives every fix exactly two levers: make the boundary byte parser-recognizable, or make the boundary byte grammar-admissible (or stop depending on the boundary at all). Route specifics:

- **(a) Full-stream grammar (grammar over the reasoning region too).** The mask gate must stop treating the reasoning phase as unmasked: constrain from the prefill bonus sample and every decode column (`engine_core.h:1414–1419`, `decode.cpp:954–982`; drop the `regions[column] != 0 → all-ones` branch at `grammar_runtime.cpp:50–52` for this mode). The served grammar must then encode the whole thinking stream, including `</think>` (the open problem named in #90) — the plain schema cannot be fed to a `<think>`-opened stream. Consequence for the parser: the channel split still runs through R2, so either the wrapper's boundary token is whitespace-followed, or R2 must be aligned with the wrapper. The dodge cannot recur: any emitted token is grammar-checked from token 0.
- **(b) In-reasoning structured output / re-attribution.** The split is not the correctness mechanism: the schema-valid value is generated (and captured) inside the reasoning interval, so the grammar must be engaged there (token 0 or after a chosen prefix) and the server must reattribute the captured value from `reasoning_content` to `content`/usage. Files: the channel publish points in `chat_parse_core.cpp` + `output_session.cpp` (channels, `preview_terminal`, response assembly), and the mask wiring as in (a) for the interval that must be schema-valid. R2/R3 stay untouched, but the documented split rule (`docs/serving.md:215–216`) and the "reasoning is free-form" assumption of the recovery layer must be revised.
- **(c) Permissive-prefix wrapper grammar.** Build one wrapper: a permissive reasoning branch, then the boundary, then the answer grammar, and engage it from token 0 (mask never inert). To fit the *existing* parser R2, the wrapper must make the byte after `</think>` an explicit required whitespace — e.g., the answer branch begins with a `"\n"`/`" "` literal (the converter's `space` is optional, `json-schema-to-grammar.cpp:229`, so `space` alone would not force the decider) so the deciding column's row admits/forces `\n` (fixing §5's root-row rejection; the current root row only admits `{`-starting tokens). Two consequences: (i) the plan must guarantee the deciding column is actually masked in-round, otherwise the accepted boundary can slip through as region-1 (draft-derived planning, `engine_core.h:1843–1851`, and commit uses the same draft regions, `commit.cpp:443–449`) — the mask lifecycle needs a rule for accepted-token corrections; (ii) performance: reasoning columns stop being "all-ones with mask inactive" and become wrapper rows (the cost analysis flagged in #90; the producer's row cache/partial paths apply). Alternatively (c) pairs with the parser lever: accept `</think>{` under a constrained request, then the `{` token is both parser-boundary and root-admissible.

Parser lever, precisely: R2's deciding-byte test (`chat_parse_core.cpp:619`) is the single line that classifies the observed stream as quoted text. Changing it naively to "any byte closes" breaks the corpus vectors that pin R3 (`tests/fixtures/chat_parsing/corpus.json:227–267` `reasoning-quoted-close-followed-by-quote`, `:302–337` split-across-rounds; `docs/serving.md:215–216`). A constrained-mode rule is required (e.g., in a constrained request the deciding set includes the answer grammar's admitted first byte, `{`), with new corpus vectors for `</think>{`, and it must be paired with the mask engaging on that same column so the answer is actually constrained.
